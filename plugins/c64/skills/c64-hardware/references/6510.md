# 6510 CPU

The C64's 6510 is an NMOS 6502 core with a 6-bit I/O port at `$00`/`$01` (see `memory-map.md`). It runs at 985,248 Hz on PAL machines and 1,022,727 Hz on NTSC machines. It has no 65C02 instructions.

## 1. Cycle rules

Each table cell reads `opcode/cycles`. The addressing mode fixes the instruction's length:

| Bytes | Modes |
| --- | --- |
| 1 | `impl`, `A` |
| 2 | `#`, `zp`, `zp,x`, `zp,y`, `(zp,x)`, `(zp),y`, `rel` |
| 3 | `abs`, `abs,x`, `abs,y`, `(abs)` |

A `+` after the count marks a read that takes 1 more cycle when the indexed address crosses a page: `abs,x`, `abs,y` and `(zp),y` reads. Stores and read-modify-write instructions always take the longer count and never vary, so `sta abs,x` is always 5 cycles, `sta (zp),y` always 6 and `inc abs,x` always 7.

Branches take 2 cycles when not taken, 3 when taken to the same page, and 4 when taken to a different page. The page compared is that of the instruction after the branch.

`(zp),y` costs 5 or 6 cycles for a read and 6 for a store. `abs,y` costs 4 or 5 for a read and 5 for a store. A pointer in zero page therefore costs 1 cycle more than an absolute table address, and it buys the ability to point anywhere.

## 3. What the undocumented opcodes do

The stable ones behave the same on every NMOS 6510 and 8500, and emulators implement them faithfully. The unstable ones depend on the chip, its temperature, or bus activity from the VIC-II, so their results vary between machines.

### Stable

| Opcode | Effect | Notes |
| --- | --- | --- |
| `LAX` | A = X = M; sets N, Z | Has no immediate form; `LXA` below is unstable. `zp,y` and `abs,y` index by Y. |
| `SAX` | M = A AND X | Leaves the flags alone. |
| `DCP` | M = M − 1, then compare A with M | With A = 0, `dcp count : bne loop` counts a memory byte down to zero in one instruction. |
| `ISC` | M = M + 1, then A = A − M − (1 − C) | Follows the decimal flag, like `SBC`. |
| `SLO` | M = M << 1, then A = A OR M | |
| `RLA` | M = M rotated left through C, then A = A AND M | |
| `SRE` | M = M >> 1, then A = A EOR M | |
| `RRA` | M = M rotated right through C, then A = A + M + C | Follows the decimal flag, like `ADC`. |
| `ANC #` | A = A AND imm; C = bit 7 of the result | Two opcodes, `$0B` and `$2B`, do the same. With an immediate below `$80`, it is `and #imm` and `clc` in 2 cycles. |
| `ALR #` | A = (A AND imm) >> 1 | C receives bit 0 of the AND result. |
| `ARR #` | A = (A AND imm) rotated right through C | C = bit 6 of the result and V = bit 6 EOR bit 5; decimal mode changes the result. |
| `SBX #` | X = (A AND X) − imm | Sets C, N and Z like `CMP` and ignores the decimal and carry flags. With A = `$FF` it subtracts a constant from X in 2 cycles, against 8 for `txa : sec : sbc #n : tax`. |
| `SBC #` (`$EB`) | Same as `$E9` | |

Undocumented NOPs with a memory operand perform the read. Aimed at an I/O register, one has that read's side effects: it clears `$DC0D`, `$DD0D`, `$D01E` or `$D01F`. The 2-byte and 3-byte forms can skip the next 1 or 2 bytes, like the `bit` trick, without touching the flags.

### Unstable

| Opcode | Effect | When it can be used |
| --- | --- | --- |
| `ANE #` (XAA) | A = (A OR magic) AND X AND imm | "magic" varies with the chip and its temperature. The result is predictable only when imm = 0 or A = `$FF`. |
| `LXA #` (`LAX #`) | A = X = (A OR magic) AND imm | Same rule as `ANE`. |
| `SHA`, `SHX`, `SHY` | M = register(s) AND (high byte of the base address + 1) | The AND term drops out when a VIC-II DMA cycle lands inside the instruction. When the index crosses a page, the stored value replaces the high byte of the target address. Safe only without a page cross and without DMA, for instance in the border with sprites off. |
| `TAS` (SHS) | S = A AND X, then M = S AND (high byte + 1) | As `SHA`, and it changes the stack pointer. |
| `LAS` (LAE) | A = X = S = M AND S | AAY64 marks it unstable; treat it as unstable. |

### JAM

The 12 JAM opcodes (`$02`, `$12`, `$22`, `$32`, `$42`, `$52`, `$62`, `$72`, `$92`, `$B2`, `$D2`, `$F2`) halt the CPU until reset, and interrupts don't reach it. A crash that freezes the machine with the screen still showing usually means execution ran into data and hit one.

## 4. NMOS quirks

- **Zero-page wrap.** `zp,x`, `zp,y`, `(zp,x)` and the pointer fetch of `(zp),y` stay inside zero page. `lda $FF,x` with X = 1 reads `$00`, not `$0100`. A `(zp),y` pointer stored at `$FF` takes its low byte from `$FF` and its high byte from `$00`.
- **Indirect jump across a page.** `jmp ($xxFF)` takes the low byte from `$xxFF` and the high byte from `$xx00`, so a jump vector must not start on a page's last byte.
- **Decimal mode.** N and V are set from the high nybble before decimal correction, and Z follows the binary result, so only C is valid after `adc` or `sbc` in decimal mode. Interrupt entry does not clear D, so a handler that does arithmetic while the main code may be in decimal mode needs its own `cld`. Reset does clear it, because the KERNAL runs `cld`.
- **Double writes.** A read-modify-write instruction (`inc`, `dec`, `asl`, `lsr`, `rol`, `ror` and the undocumented RMW opcodes) writes the unmodified value back, then the new one. An I/O register sees both writes. `inc $D019` and `asl $D019` acknowledge VIC-II interrupts only because of that first write, and a 65816 in native mode, such as a SuperCPU, skips it.
- **Dummy reads.** An indexed read that crosses a page first reads from the wrong page, the base high byte with the indexed low byte. A store or RMW with `abs,x`, `abs,y` or `(zp),y` always performs that extra read. When the extra read hits `$DC0D`, `$DD0D`, `$D01E` or `$D01F`, it clears the register.
- **BRK.** `BRK` is 2 bytes long: it pushes the address of the instruction plus 2, so the byte after it is skipped on return. The B flag exists only in the copy of P that BRK pushes. BRK shares the IRQ vector, and the KERNAL's dispatcher checks the pushed B flag to tell the two apart.
- **No 65C02 instructions.** `BRA`, `PHX`, `PHY`, `PLX`, `PLY`, `STZ`, `TRB`, `TSB`, `INC A`, `DEC A`, `(zp)` addressing, `BIT #`, `JMP (abs,x)`, `WAI`, `STP`, `BBR`, `BBS`, `RMB` and `SMB` don't exist. Their opcodes run as undocumented NOPs, other undocumented opcodes, or JAM.

## 5. Interrupts

- The CPU checks for an interrupt at the end of each instruction. The entry sequence then takes 7 cycles: it pushes PC and P, sets I, and fetches the vector. The handler's first cycle therefore varies with the instruction in progress when the interrupt arrived: by up to 7 cycles with official opcodes, 8 with the undocumented `(zp,x)` and `(zp),y` read-modify-writes, and a whole line when a badline stalls the CPU.
- `RTI` takes 6 cycles and restores P, so the I flag returns to its state before the interrupt.
- IRQ is level-triggered: it fires again after `RTI` if the source still holds it, which is why every handler must acknowledge its source. NMI is edge-triggered: CIA 2 holds the NMI line low until `$DD0D` is read, and no new NMI can fire until then.
- The hardware vectors are `$FFFA` (NMI), `$FFFC` (reset) and `$FFFE` (IRQ and BRK). With the KERNAL banked in, they lead to its dispatchers, which add cycles (see `memory-map.md`, section "KERNAL interrupt entry and exit").

## 6. Padding and delay idioms

| Cycles | Code | Bytes | Side effects |
| --- | --- | --- | --- |
| 2 | `nop` | 1 | none |
| 3 | `nop zp` (`$04`) | 2 | none; performs a read |
| 3 | `bit zp` | 2 | changes N, V, Z |
| 3 | `jmp *+3` | 3 | none |
| 4 | `nop abs` (`$0C`) or `nop zp,x` (`$14`) | 3 / 2 | none; performs a read |
| 5 | `nop` + `nop zp` | 3 | none |
| 7 | `pha` + `pla` | 2 | changes N, Z; uses a stack byte |

Any count of 2 or more is a sum of 2s and 3s. A loop `ldx #n : dex : bne *-1` takes 5n + 1 cycles when the branch stays in its page: 2 for the `ldx`, 5 for each pass, and 1 less for the final untaken branch.
